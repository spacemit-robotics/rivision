# 基于 SpacemiT K3 的视频摘要应用

> **一句话价值主张**：1 小时视频，8 分钟出报告，每路摄像头成本不到 300 元。

---

## 1. 产品定义

视频摘要是一种基于**视觉语言大模型（VLM）**的智能视频分析技术。系统通过对视频流进行关键帧提取，利用部署在 SpacemiT K3 RISC-V 芯片上的 QWen3-VL-2B 视觉语言模型自动理解画面内容，生成结构化的文字描述和分析报告，实现视频内容的**自动讲解和说明**。

核心能力：
- **视觉理解**：基于 QWen3-VL-2B 视觉语言模型，对每一帧画面进行场景描述、人物识别、行为分析
- **语义生成**：将视觉分析结果整合为连贯的时间线文字摘要
- **事件检测**：自动识别异常事件（人员聚集、跌倒、入侵等），关联知识库给出处置建议
- **多场景模板**：支持安防、交通、工业、零售等多种场景的专用分析 Prompt

### 2.2 K3 芯片硬件能力

| 硬件单元 | 规格 | 在视频摘要中的作用 |
|---------|------|------------------|
| CPU | 8 核 RISC-V (RVV 1.0) | 基于llama.cpp的SpaceMIT推理引擎，VLM 推理主力 |
| NPU | 60TOPS INT4 | YOLO11n 目标检测，10-20ms/帧 |
| VPU | H.264/H.265 硬解码 | 视频流硬件解码，释放 CPU 算力 |
| DDR | LPDDR5x 8GB | 模型权重加载 + 推理中间结果缓存 |
| 功耗 | 10-15W (全负载) | 7×24 小时运行 |

### 2.3 数据流程（端到端）

```
步骤 1: 视频接入
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  输入源                    处理                         输出
  ─────                    ────                         ────
  本地视频文件    ─┐
  RTSP 网络流     ─┼──→  K3 VPU 硬件解码  ──→  原始帧序列 (NV12/RGB)
  文件夹批量扫描  ─┘      SpacemiT MPP

步骤 2: 关键帧提取
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  模式              算法                              输出
  ────              ────                              ────
  固定间隔模式  →  每 N 秒取 1 帧 (默认 5s)     ─┐
  智能提取模式  →  帧差法检测画面变化 >阈值      ─┼──→  关键帧队列
                   场景切换检测                   ─┘     (JPEG + 时间戳)

步骤 3: AI 推理 (K3 芯片核心环节)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  关键帧 ──→ [K3 NPU] YOLO 检测 (10-20ms)
              │         输出: 目标框 + 类别 + 置信度
              ↓
         [SpaceMIT推理引擎] QWen3-VL-2B 视觉理解 (30-50s)
              │         输入: 关键帧 + 场景 Prompt
              │         输出: 结构化 JSON 描述
              ↓
         {
           "scene": "办公室走廊",
           "people_count": 3,
           "risk_level": "low",
           "description": "三名员工正常通行，未见异常",
           "objects": ["person", "backpack"]
         }

步骤 4: 事件检测与分类
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  VLM 输出 ──→ 三级匹配引擎:
                ├─ L1: 关键词匹配 (快速, <1ms)
                │      规则: "跌倒|入侵|火灾|打架"
                ├─ L2: 语义匹配 (Transformers, ~50ms)
                │      余弦相似度 > 0.75 触发
                └─ L3: 知识库匹配 (ChromaDB 向量检索)
                       关联历史案例和处置规程
                ↓
         事件记录 + 风险等级 (info/warning/critical)

步骤 5: 摘要生成与输出
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  所有帧分析结果 ──→ 时间线聚合
                      ├─ 按时间排序
                      ├─ 相似事件合并 (时间窗口 30s)
                      ├─ 风险事件高亮标注
                      └─ 生成结构化摘要报告
                           ↓
                      WebSocket 实时推送:
                      ├─ 分析进度 (已处理帧数/总帧数)
                      ├─ 实时事件告警 (critical 立即推送)
                      └─ 摘要完成通知
```

### 2.4 模块详细描述

#### 模块 A: 帧提取引擎

| 属性 | 说明 |
|------|------|
| 输入 | 视频文件路径 / RTSP URL |
| 输出 | 关键帧 JPEG + 时间戳列表 |
| K3 加速 | VPU 硬件解码 H.264/H.265，CPU 零负载 |
| 固定模式 | 每 N 秒提取 1 帧，适合长视频快速浏览 |
| 智能模式 | 帧差法 + 场景切换检测，减少冗余帧 |
| 并发能力 | 单 K3 节点支持 4 路视频同时提取 |

#### 模块 B: VLM 推理引擎 (K3 核心模块)

| 属性 | 说明 |
|------|------|
| 模型 | QWen3-VL-2B (~2GB) |
| 运行时 | 基于llama.cpp的SpaceMIT推理引擎 |
| K3 加速原理 | SpaceMIT推理引擎深度优化矩阵乘法和注意力计算 |
| VLM推理延迟 | 30-50 秒/帧 (取决于输出 token 长度) |
| 上下文窗口 | 4096 tokens |
| 内存占用 | ~4GB (模型权重) + ~1GB (KV Cache) |
| 并发 | 单节点 1 并发，多节点通过 Gateway 负载均衡 |
| Prompt 模板 | 5 种场景模板 (安防/交通/工业/零售/通用) |

#### 模块 C: 事件分类引擎

| 属性 | 说明 |
|------|------|
| L1 关键词 | 正则匹配，延迟 <1ms，覆盖高频事件关键词 |
| L2 语义 | Transformers 向量化，余弦相似度 >0.75 触发 |
| L3 知识库 | ChromaDB 向量检索，关联历史案例和处置规程 |
| 事件级别 | info / warning / critical 三级分类 |
| 去重机制 | 30 秒时间窗口内相同事件自动合并 |

#### 模块 D: 推理调度层

| 属性 | 说明 |
|------|------|
| Direct 模式 | 单节点直连 llama.cpp，适合 1-2 路视频 |
| Gateway 模式 | rivision-gateway 多节点负载均衡，适合 3+ 路视频 |
| 调度策略 | Round-Robin / Least-Loaded 可配置 |
| 并发控制 | 最多 10 帧并行推理 (跨节点分发) |
| 超时处理 | 单帧超时 60s 自动跳过，不阻塞后续帧 |
| 故障转移 | 节点心跳超时自动摘除，任务迁移到健康节点 |

### 2.5 分析模式与 Prompt 工程

| 模式 | Prompt 关注点 | 输出字段 | 典型场景 |
|------|-------------|---------|---------|
| 通用模式 | 全面场景描述 | scene, people, objects, activity | 视频回顾 |

## 3. 核心优势

### 3.1 K3 方案 vs 传统方案

| 对比维度 | GPU 云端方案 | 边缘 AI 盒子 (ARM) | SpacemiT K3 方案 |
|---------|------------|-------------------|-----------------|
| 硬件成本 | GPU 服务器 5-20 万 | 3000-8000 元/台 | ~2000 元/节点 |
| 功耗 | 300-1000W | 30-60W | 10-15W/节点 |
| VLM 能力 | 有 (大模型) | 无/有限 | 有 (QWen3-VL-2B, SpaceMIT推理引擎加速) |
| 网络依赖 | 高 (视频上传) | 低 | 无 (本地处理) |
| 隐私保护 | 差 (数据上云) | 好 | 好 (数据不出本地) |
| 扩展方式 | 换更贵 GPU | 买更多盒子 | 加 K3 节点 (~2000元) |
| 月度费用 | 云服务费 | 无 | 无 |

### 3.2 客户痛点与解决方案

| 客户痛点 | K3 方案如何解决 |
|---------|---------------|
| 人工回看视频耗时耗力 | AI 自动分析，1 小时视频 8 分钟出报告 |
| 云端方案月费高昂 | 一次购买，零月费，零云端依赖 |
| 视频上云有隐私合规风险 | 所有数据本地处理，满足数据安全法规 |
| GPU 服务器功耗高、部署复杂 | 10-15W 功耗，即插即用 |
| 传统 NVR 只能录不能"看懂" | VLM 理解画面内容，生成自然语言描述 |
| 扩容成本高 | 加一个 K3 节点仅 ~2000 元 |

### 3.3 K3 芯片核心技术优势

- **SpaceMIT推理引擎加速**：基于llama.cpp深度优化，矩阵运算加速 3-5x（相比标量模式）
- **NPU 60TOPS**：YOLO11n INT8 推理仅 10-20ms，释放 CPU 全部算力给 VLM
- **VPU 硬解码**：H.264/H.265 硬件解码，视频接入零 CPU 开销
- **极致功耗比**：10-15W 功耗下完成 VLM + YOLO 双模推理
- **分布式线性扩展**：N 个 K3 节点 = N 倍处理能力，Gateway 自动调度
- **开放模型生态**：支持 GGUF 格式模型，HuggingFace 社区模型即插即用

## 4. 应用场景

### 4.1 安防巡检自动化

**部署规模**：2-4 个 K3 节点，8-16 路摄像头

**数据流**：
```
24h 监控录像 → 定时任务 (凌晨触发) → K3 VPU 解码 → 帧提取
→ K3 NPU YOLO 检测 → SpaceMIT推理引擎 VLM 安防模式分析
→ 事件检测 (入侵/聚集/跌倒) → 生成安防摘要报告 → 推送安保主管
```

**客户价值**：替代人工回看，1 小时录像 8 分钟出报告，覆盖全部摄像头，零遗漏

### 4.2 交通事件回顾

**部署规模**：4-8 个 K3 节点，16-32 路路口摄像头

**数据流**：
```
路口视频流 → K3 VPU 实时解码 → K3 NPU YOLO 检测 (车辆/行人)
→ 异常触发 VLM 分析 → 违规行为描述 (闯红灯/逆行/违停)
→ 事件记录 + 证据截图 → 每日交通摘要报告
```

**客户价值**：自动识别违规并精确定位时间点，减少人工审核工作量 90%

### 4.3 工业安全监管

**部署规模**：2-4 个 K3 节点，8-16 路车间摄像头

**数据流**：
```
车间视频 → K3 VPU 解码 → K3 NPU YOLO 检测 (人员/设备)
→ SpaceMIT推理引擎 VLM 工业模式分析 → 安全装备检测 (安全帽/反光衣)
→ 危险行为识别 → 实时告警 (critical) + 每班次安全报告
```

**客户价值**：7×24 安全监管无死角，事故预防，合规报告自动生成

### 4.4 零售门店运营

**部署规模**：1-2 个 K3 节点，4-8 路门店摄像头

**数据流**：
```
门店视频 → K3 VPU 解码 → K3 NPU YOLO 客流计数
→ SpaceMIT推理引擎 VLM 零售模式分析 → 热区停留分析 → 顾客行为洞察
→ 每日运营摘要 (客流趋势/热区分布/异常事件)
```

**客户价值**：数据驱动运营决策，无需额外传感器，隐私合规（数据不出店）

### 4.5 教育培训

**部署规模**：1 个 K3 节点，1-2 路教室摄像头

**数据流**：
```
课堂录像 → K3 VPU 解码 → 智能帧提取 (板书变化/PPT切换)
→ SpaceMIT推理引擎 VLM 通用模式 → 知识点提取 → 时间线索引 → 课程摘要
```

**客户价值**：长视频快速回顾，按知识点检索，学习效率提升
