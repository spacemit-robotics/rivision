# 基于 SpacemiT K3 的分布式视频推理网关应用

> **一句话价值主张**：每路摄像头 AI 分析成本仅 ~300 元，10-15W 功耗 7×24 运行，从 1 节点到 32 节点无缝扩展。

---

## 1. 产品定义

分布式视频推理网关是一种面向视频流 AI 分析的**边缘计算基础设施**，基于 SpacemiT K3 RISC-V 芯片集群，将 AI 推理能力从集中式 GPU 服务器下沉到多个低功耗边缘节点，通过统一的推理网关实现任务调度、负载均衡和结果聚合。

系统核心定位：
- **推理底座**：为 YOLO 目标检测、VLM 视觉语言模型等提供统一的推理服务接口
- **分布式调度**：将推理任务智能分发到多个 K3 节点，实现并行处理
- **弹性扩展**：按需增减节点，从单节点到 32 节点集群无缝扩展
- **协议网关**：统一接入 GB28181、ONVIF、RTSP 等多种视频协议

### 2.2 K3 芯片硬件能力

| 硬件单元 | 规格 | 在推理网关中的作用 |
|---------|------|------------------|
| CPU | 8 核 RISC-V (RVV 1.0) | VLM 推理主力，基于llama.cpp的SpaceMIT推理引擎 |
| NPU | 60TOPS INT4 | YOLO 目标检测，10-20ms/帧 |
| VPU | H.264/H.265 硬解码 | 视频流硬件解码，释放 CPU 算力 |
| DDR | LPDDR5x 8GB | 模型权重 + 推理中间结果 |
| 网络 | GbE | 节点间通信 + 视频流接入 |
| 功耗 | 10-15W | 7×24 全负载运行 |

### 2.3 核心组件

#### rivision-cli（主控服务）
- 摄像头管理和流分发
- YOLO 检测任务调度（轮询/负载均衡）
- VLM 图像理解触发
- 检测结果存储和查询
- 集成 go2rtc 流媒体引擎（WebRTC/HLS/RTSP 转发）
- Web UI 管理界面

#### rivision-gateway（推理网关）
- 统一推理 API 接口
- 多节点负载均衡
- 请求转发和结果聚合
- 节点健康检查和故障转移
- 支持 VLM 和 Embedding 两类推理请求

#### rivision-node（推理节点）
- **Node Agent**：节点注册、心跳上报、进程管理
- **YOLO Server**：基于 OnnxRuntime + SpacemiT NPU EP 的目标检测
- **llama.cpp Server**：多模态 VLM 推理（Qwen3-VL-2B）

#### rivision-owl（流媒体服务）
- GB28181 国标协议信令处理
- ONVIF 设备发现和控制
- ZLMediaKit 流媒体转发
- 设备注册和状态管理

#### rivision-embed（向量化服务）
- 文本向量化（ONNX Runtime）
- 检测结果语义索引
- 支持语义检索

### 2.5 节点管理

| 机制 | 说明 |
|------|------|
| 自动注册 | Node Agent 启动后自动向 Host 注册 |
| 心跳检测 | 定期上报节点状态（CPU/内存/NPU/推理队列） |
| 负载均衡 | 基于节点负载的智能任务分发 |
| 故障转移 | 节点离线自动将任务迁移到其他节点 |
| 热插拔 | 支持运行时增减节点，无需重启服务 |

## 3. 核心优势

### 3.1 K3 方案 vs 传统方案

| 维度 | GPU 集中式方案 | 边缘 AI 盒子 (ARM) | RiVision K3 方案 |
|------|-------------|-------------------|-----------------|
| 硬件成本 | 5-20 万/台 | 6000-8000/台 | ~2000 元/节点 |
| 功耗 | 300-1000W | 30-60W | 10-15W/节点 |
| 扩展方式 | 换更贵的 GPU | 买更多盒子 | 加 K3 节点 |
| 扩展粒度 | 粗（整台服务器） | 中（整个盒子） | 细（单个节点） |
| 网络依赖 | 高（视频回传） | 低 | 低 |
| 部署复杂度 | 高（机房） | 中 | 低（即插即用） |
| 模型更新 | 集中更新 | 逐台更新 | 集群统一推送 |
| VLM 能力 | 有 (大模型) | 无/有限 | 有 (Qwen3-VL-2B) |

### 3.2 客户痛点与解决方案

| 客户痛点 | K3 方案如何解决 |
|---------|---------------|
| GPU 服务器成本高、功耗大 | 单节点 ~2000 元，10-15W 功耗 |
| 视频回传带宽压力大 | 边缘推理，视频不出本地 |
| 扩容需要整台服务器 | 按需加节点，最小粒度扩展 |
| 多协议摄像头接入复杂 | GB28181/ONVIF/RTSP 全协议覆盖 |
| 节点运维管理困难 | 自动注册、心跳检测、故障转移 |
| 只有检测没有理解 | YOLO 检测 + VLM 语义理解双模推理 |

### 3.3 K3 芯片核心技术优势

- **极致性价比**：单路摄像头 ~300 元 AI 分析成本，10-15W 功耗
- **线性扩展**：1→32 节点无缝扩展，处理能力与节点数成正比
- **双模推理**：YOLO 实时检测 (10-20ms) + VLM 语义理解 (30-50s)，兼顾速度和深度
- **RISC-V 原生**：针对 SpacemiT K3 NPU 深度优化，基于llama.cpp的SpaceMIT推理引擎充分释放硬件性能
- **全协议覆盖**：GB28181/ONVIF/RTSP/WebRTC/HLS，兼容所有主流监控设备
- **边缘自治**：本地完成全部推理，不依赖云端，满足数据安全和低延迟要求
- **开放架构**：支持 ONNX/llama.cpp 等开放格式，模型可替换升级
- **运维简单**：节点自动注册、心跳检测、故障转移，无需专业运维

### 3.4 性能指标 (SpacemiT K3)

## 4. 应用场景

### 4.1 智慧园区安防

**部署规模**：4-8 个 K3 节点，16-32 路摄像头

**数据流**：
```
园区摄像头 (RTSP/ONVIF) → rivision-owl → go2rtc
→ K3 NPU YOLO 检测 (10-20ms): 人员/车辆/物品
→ 事件触发 VLM 分析: "有人在非工作时间进入仓库区域"
→ 告警推送 + 事件录像 + 语义检索索引
```

**客户价值**：全天候人员/车辆检测，VLM 场景理解自动生成事件描述，GB28181 对接现有监控平台

### 4.2 智慧交通

**部署规模**：8-16 个 K3 节点，32-64 路摄像头

**数据流**：
```
路口摄像头 (GB28181) → rivision-owl → go2rtc
→ K3 NPU YOLO: 车辆检测 + 车型识别 + 车流统计
→ 违规触发 VLM: "白色轿车闯红灯，车牌区域已截取"
→ 多路口联合分析 → 拥堵预警 + 违规记录
```

**客户价值**：自动识别违规行为，多路口联合分析，减少人工审核工作量 90%

### 4.3 智慧工厂

**部署规模**：4-8 个 K3 节点，8-32 路摄像头

**数据流**：
```
车间摄像头 → K3 VPU 解码 → K3 NPU YOLO
→ 安全装备检测 (安全帽/反光衣/护目镜)
→ 危险区域入侵检测 → VLM 描述异常行为
→ 实时告警 + 每班次安全报告
```

**客户价值**：7×24 安全监管无死角，事故预防，合规报告自动生成

### 4.4 智慧零售

**部署规模**：1-4 个 K3 节点，4-16 路摄像头

**数据流**：
```
门店摄像头 → K3 VPU 解码 → K3 NPU YOLO 客流计数
→ 热区停留分析 → 顾客行为洞察
→ 异常事件检测 (盗窃/纠纷) → VLM 描述 → 告警
→ 每日运营摘要报告
```

**客户价值**：一套设备兼顾安防 + 运营分析，数据驱动决策

### 4.5 智慧社区

**部署规模**：2-4 个 K3 节点，8-16 路摄像头

**数据流**：
```
社区摄像头 → K3 VPU 解码 → K3 NPU YOLO
→ 出入口人员/车辆管理 + 公共区域安全监控
→ 高空抛物检测 + 消防通道占用检测
→ VLM 描述 → 物业告警 + 事件记录
```

**客户价值**：提升社区安全管理水平，减少物业人力投入
