# 基于 SpacemiT K3 的 Frigate 家庭算力盒子

> **一句话价值主张**：不只是录像机，是能看懂画面的智能安防助手，<15W 功耗无风扇静音运行，零月费零云端依赖。

---

## 1. 产品定义

家庭算力盒子是一款基于 SpacemiT K3 RISC-V 芯片的**家庭级智能安防设备**，将开源 NVR 系统 Frigate 与 RiVision 分布式 AI 推理能力深度融合，为家庭和小型商业场景提供本地化、低功耗、高智能的视频监控和 AI 分析服务。

核心理念：
- **本地优先**：所有 AI 推理在 K3 芯片本地完成，视频数据不上云，保护家庭隐私
- **低功耗长运行**：单节点 <15W 功耗，7×24 小时静音运行，无风扇被动散热
- **即插即用**：开箱连接摄像头即可使用，Frigate Web UI 零配置上手
- **AI 增强**：不仅是录像机，更是智能安防助手，K3 NPU + VLM 能理解画面内容

### 2.2 K3 芯片硬件能力

| 硬件单元 | 规格 | 在家庭算力盒子中的作用 |
|---------|------|---------------------|
| CPU | 8 核 RISC-V (RVV 1.0) | VLM 推理 + 系统服务 + Frigate 运行 |
| NPU | 60TOPS INT4 | YOLO 目标检测，10-20ms/帧 |
| VPU | H.264/H.265 硬解码 | 多路摄像头视频流硬件解码 |
| DDR | LPDDR5x 8GB | Frigate + YOLO + VLM 并行运行 |
| 存储 | microSD / NVMe | 录像存储 (支持 1-4TB) |
| 网络 | GbE + WiFi 6 | 摄像头接入 + 局域网访问 |
| 功耗 | <5W (全负载) | 无风扇被动散热，静音运行 |
| 尺寸 | ~信用卡大小 | 隐蔽部署，不占空间 |

### 2.3 数据流程

```
数据流 1: 实时检测 (主流程)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  摄像头 (RTSP)
       ↓
  go2rtc 流媒体引擎 (K3 VPU 硬件解码)
       ↓
  Frigate 运动检测 (像素级变化检测，CPU 轻量计算)
       ↓ (仅运动区域有变化时触发)
  Inference Gateway Plugin → rivision-worker YOLO Server
       ↓                      [K3 NPU, 10-20ms]
  检测结果: {class: "person", confidence: 0.92, bbox: [...]}
       ↓
  Frigate 事件管理器
       ├─ 创建事件记录 (SQLite)
       ├─ 生成缩略图 + 视频片段
       ├─ MQTT 发布事件 → Home Assistant 联动
       └─ Web UI 实时更新

数据流 2: VLM 场景描述 (增强流程)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  YOLO 检测到目标 (person/car)
       ↓ (触发条件: 新目标出现 / 置信度 > 阈值)
  Inference Gateway Plugin → rivision-worker llama.cpp Server
       ↓                      [SpaceMIT推理引擎, 30-50s]
  场景描述: "门口有一个穿蓝色外套的陌生人正在按门铃，
            手中拿着一个快递包裹"
       ↓
  Frigate 事件更新 (附加描述)
       ├─ 告警推送 (含场景描述，无需查看视频)
       └─ 事件搜索索引

数据流 3: 录像与回放
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  摄像头 RTSP 流
       ↓
  go2rtc → 连续录像 (H.265 编码，K3 VPU)
       ↓
  存储管理:
       ├─ 连续录像: 循环覆盖 (按存储容量)
       ├─ 事件录像: 事件前 5s + 事件后 10s 保留
       └─ 自动清理: 超过保留天数自动删除

数据流 4: Home Assistant 联动
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Frigate 检测事件
       ↓ MQTT
  Home Assistant 自动化:
       ├─ 检测到人 → 开启门廊灯
       ├─ 检测到车 → 开启车库灯
       ├─ 深夜检测到人 → 触发警报 + 推送通知
       └─ 检测到宠物 → 不触发告警 (过滤)
```

### 2.4 模块详细描述

#### 模块 A: Frigate NVR 核心

| 属性 | 说明 |
|------|------|
| 版本 | Frigate (适配 K3) |
| 运动检测 | 像素级变化检测，可配置灵敏度和区域 |
| 事件管理 | 自动创建/合并/关闭事件，生成缩略图 |
| 录像策略 | 连续录像 + 事件录像，可配置保留天数 |
| 区域规则 | 多边形区域定义，每区域独立检测配置 |
| Web UI | 实时预览、事件回放、配置管理 |

#### 模块 B: Inference Gateway Plugin

| 属性 | 说明 |
|------|------|
| 类型 | Frigate 自定义检测器插件 |
| 接口 | HTTP API 对接 rivision-worker |
| Detection 模式 | YOLO 目标检测，返回 bbox + class + confidence |
| Description 模式 | VLM 场景描述，返回自然语言描述 |
| 超时 | 60s (VLM) / 1s (YOLO) |
| 降级 | 推理节点离线时降级为纯运动检测 |

#### 模块 C: rivision-worker (K3 本地推理)

| 属性 | 说明 |
|------|------|
| YOLO Server | ONNX Runtime + SpacemiT NPU EP |
| YOLO 模型 | YOLO11n INT8 (~10MB) |
| YOLO 延迟 | 10-20ms/帧 (640×640) |
| YOLO 类别 | 80 类 COCO (人/车/动物/物品等) |
| VLM Server | 基于llama.cpp的SpaceMIT推理引擎 |
| VLM 模型 | Qwen3-VL-2B (~4GB) |
| VLM 延迟 | 30-50s/请求 |
| 资源分配 | NPU → YOLO, CPU → VLM (SpaceMIT推理引擎) |

#### 模块 D: 存储与通信

| 属性 | 说明 |
|------|------|
| 事件数据库 | SQLite (事件记录、检测结果) |
| 录像存储 | microSD / NVMe (1-4TB) |
| 消息总线 | MQTT (Frigate ↔ Home Assistant) |
| 流媒体 | go2rtc (WebRTC/HLS 本地播放) |

## 3. 核心优势

### 3.1 K3 方案 vs 市场产品

| 维度 | 传统 NVR | 云端 AI 摄像头 | 群晖 NAS | SpacemiT K3 家庭算力盒子 |
|------|---------|-------------|---------|---------------|
| AI 能力 | 无/基础运动检测 | 云端 AI (有限) | 有限本地 AI | K3 NPU YOLO + VLM |
| 场景理解 | 无 | 基础标签 | 无 | VLM 自然语言描述 |
| 隐私保护 | 好 (本地) | 差 (上云) | 好 (本地) | 好 (本地) |
| 月费 | 无 | 有 (云服务) | 无 | 无 |
| 功耗 | 10-30W | 5-10W/个 | 30-60W | <5W |
| 价格 | 500-2000 | 200-500/个 | 3000-8000 | ~1000 |
| 扩展性 | 固定通道 | 按摄像头买 | 有限 | 加 K3 节点 |
| 开源生态 | 封闭 | 封闭 | 部分开放 | 完全开源 (Frigate) |
| 智能家居 | 不支持 | 有限 | 有限 | Home Assistant 原生 |

### 3.2 客户痛点与解决方案

| 客户痛点 | K3 方案如何解决 |
|---------|---------------|
| 传统摄像头只能录不能"看懂" | VLM 理解画面内容，推送自然语言描述 |
| 云端摄像头有隐私泄露风险 | 所有数据本地处理，零云端依赖 |
| 云端摄像头需要月费订阅 | 一次购买，零月费 |
| 运动检测误报多 (树叶/宠物) | NPU YOLO 精确识别，区分人/车/动物 |
| NVR 功耗高、噪音大 | <15W 无风扇静音，年电费 <100 元 |
| 智能家居联动困难 | Home Assistant 原生集成，MQTT 事件驱动 |

### 3.3 K3 芯片核心技术优势

- **VLM 场景理解**：不仅检测"有人"，还能描述"穿蓝色外套的陌生人在按门铃"
- **NPU 精确检测**：K3 NPU 60TOPS，YOLO 10-20ms，区分人/车/动物，大幅减少误报
- **超低功耗**：<15W 全天候运行，年电费 <100 元，无风扇静音
- **隐私零妥协**：所有数据本地处理，无云端依赖，无订阅费用
- **Frigate 生态**：兼容 Frigate 社区插件 + Home Assistant 智能家居联动
- **开源透明**：代码完全开源，用户可审计、可定制

|------|---------|-----------|---------------|

## 4. 应用场景

### 4.1 家庭安防

**部署**：1 个 K3 节点 + 2-4 个摄像头（门口、车库、后院）

**数据流**：
```
摄像头 → K3 VPU 解码 → Frigate 运动检测 → K3 NPU YOLO
→ 人员检测 → SpaceMIT推理引擎 VLM 描述 → 手机推送 (含场景描述)
→ Home Assistant 联动 (开灯/录像/警报)
```

**典型告警**：
- "门口有陌生人按门铃，手持快递包裹" → 正常，不触发警报
- "凌晨 2 点后院有人翻越围栏" → 触发警报 + 录像 + 推送

### 4.2 小型店铺

**部署**：1-2 个 K3 节点 + 4-8 个摄像头

**数据流**：
```
店内摄像头 → K3 VPU 解码 → K3 NPU YOLO 客流检测
→ 营业时间: 客流统计 + 热区分析
→ 非营业时间: 入侵检测 + VLM 描述 → 告警推送店主
```

**客户价值**：一套设备兼顾安防 + 运营分析，无月费

### 4.3 老人/儿童看护

**部署**：1 个 K3 节点 + 1-2 个室内摄像头

**数据流**：
```
室内摄像头 → K3 VPU 解码 → K3 NPU YOLO 人员检测
→ 行为分析: 跌倒检测 / 长时间静止检测
→ SpaceMIT推理引擎 VLM: "老人在客厅沙发上已静止超过30分钟"
→ 告警推送家属
```

**隐私保护**：所有数据本地处理，视频不出家门，尊重老人隐私

### 4.4 Home Assistant 智能家居联动

**联动场景**：
- 检测到人 → 开门廊灯 + 推送通知
- 检测到车 → 开车库灯
- 深夜检测到人 → 全屋灯光 + 警报 + 录像
- 检测到宠物 → 不触发任何动作

### 4.5 别墅/庄园

**部署**：2-4 个 K3 节点 + 8-16 个摄像头

**数据流**：
```
周界摄像头 → K3 NPU YOLO 检测 → 区域入侵判断
→ VLM 描述 → 多区域联动告警 → 推送 + 录像保存
```

**K3 优势**：多节点覆盖大面积区域，总功耗 <15W，无需布线供电
