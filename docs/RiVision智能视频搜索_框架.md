## 1. 系统概述

### 1.1 系统定位

RiVision是一套基于K3边缘AI芯片的分布式视频分析和智能搜索系统，通过充分利用边缘节点的异构计算资源（CPU、NPU、VPU），实现低成本、高性能、可伸缩的智能视频分析/搜索的解决方案。

### 1.2 核心目标

| 目标 | 描述 |
|------|------|
| **伸缩性** | 支持节点动态增减，自动负载均衡，故障自动转移 |
| **性能最优** | 最大化硬件资源利用率，最小化推理延迟和成本 |
| **易用性** | 通过统一API和Web界面，简化系统集成和运维 |

### 1.3 核心功能

- **智能视频分析**：实时目标检测、行为识别、场景理解
- **多模态搜索**：自然语言搜索、以图搜图、混合搜索
- **知识库驱动**：基于规则的智能告警、业务建议生成
- **分布式处理**：边缘推理、本地存储、中心聚合

### 1.4 目标场景

- **安防监控**：智能目标搜索、异常行为检测、规则告警
- **零售商场**：VIP识别、客流分析、热区统计、智能导购

### 1.5 产品形态

| 产品形态 | 目标客户 | 规格 | 典型场景 |
|----------|----------|------|----------|
| **AI算力盒子 (Lite)** | 个人/家庭 | 1-2节点，4-8路摄像头 | 基于Frigate的智能家居安防 |
| **AI算力盒子 (Pro)** | 独立零售店铺 | 1-4节点，4-16路摄像头 | 单店客流分析、VIP识别 |
| **AI服务器 2U (标准版)** | 物业/园区 | 1-16节点，4-64路摄像头 | 园区安防、停车管理 |
| **AI服务器 2U (企业版)** | 商业体/连锁 | 1-32节点，4-128路摄像头 | 商场客流、连锁门店 |

**扩展规则**：每算力节点基于K3 SoC，支持4路1080P摄像头，按需增加节点即可线性扩容。

#### 4.1.2 子模块说明

| 子模块 | 进程/端口 | 功能 | 硬件加速 |
|--------|----------|------|----------|
| **rivision_worker** | :9181 (C++) | 节点编排、配置管理、事件上报、健康检查、搜索、规则、YOLO检测、VLM推理 | CPU + NPU + SMT + VPU |
| **Stream Manager** | 内嵌 Worker + go2rtc :1984 | RTSP/ONVIF接入、VPU硬解码、智能抽帧、WebRTC/HLS输出 | VPU |
| **rivision_embed** | :18081 (Go, HTTP) | 文本/图像向量化 (Chinese-CLIP-ViT-B/16, 512D) | NPU |
| **Vector Store** | 内嵌 Worker | SQLite本地向量存储 + 暴力余弦 (100万级) | CPU |
| **Knowledge Base** | 内嵌 Worker | 本地规则和特征库 (从 Hub 同步) | CPU |
| **Emotion Analyzer** | 内嵌 Worker | VLM情感分析 (happy/sad/angry/surprised/neutral等) → 统计 + emotion_negative规则触发 | SMT |
| **Posture Classifier** | 内嵌 Worker | COCO 17关键点姿态分类 (standing/sitting/crouching/fallen/bending) + VLM fallback | CPU + SMT |
| **Item Tracker** | 内嵌 Worker | 物品追踪状态机 (new→present→stationary→removed) → abandoned_object/object_removed规则 | CPU |

> **注意**: v2.0 架构中 YOLO 和 VLM 推理已合并到 `rivision_worker` (C++ 服务);
> Embed 为独立进程 `rivision_embed`; 视频流通过 go2rtc 代理。

### 5.4 混合搜索算法

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         混合搜索评分算法                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  输入:                                                                       │
│    text_query: "穿红衣服的女性"                                              │
│    image_query: [上传图片的向量]                                             │
│    text_weight: 0.6 (默认)                                                  │
│    image_weight: 0.4 (默认)                                                 │
│                                                                              │
│  处理流程:                                                                   │
│  ────────────────────────────────────────────────────────────────────────   │
│                                                                              │
│  1. 向量化                                                                   │
│     text_vec = CLIP.encode_text(text_query)     # 512D                      │
│     image_vec = CLIP.encode_image(image_query)  # 512D                      │
│                                                                              │
│  2. 搜索模式判断                                                             │
│     if text_query != "" and image_query == null:                            │
│         mode = "text_only"                                                  │
│         text_weight = 1.0, image_weight = 0                                 │
│     elif text_query == "" and image_query != null:                          │
│         mode = "image_only"                                                 │
│         text_weight = 0, image_weight = 1.0                                 │
│     else:                                                                    │
│         mode = "hybrid"                                                     │
│         # 使用用户指定或默认权重                                             │
│                                                                              │
│  3. 相似度计算                                                               │
│     for each detection in database:                                         │
│         # 余弦相似度                                                        │
│         text_sim = cosine(text_vec, detection.text_embedding)               │
│         image_sim = cosine(image_vec, detection.image_embedding)            │
│                                                                              │
│         # 加权融合                                                           │
│         base_score = text_weight * text_sim + image_weight * image_sim      │
│                                                                              │
│  4. 关键词加成                                                               │
│     keywords = extract_keywords(text_query)  # ["红", "衣服", "女性"]       │
│     keyword_boost = 0                                                       │
│     for kw in keywords:                                                     │
│         if kw in detection.description:                                     │
│             keyword_boost += 0.05                                           │
│                                                                              │
│     final_score = base_score + min(keyword_boost, 0.15)                     │
│                                                                              │
│  5. 排序返回                                                                 │
│     results = sort_by_score(detections)                                     │
│     return results[:limit]                                                  │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.4 层级集群模式 (G6: 500+门店)

当部署规模超过约125个Worker（500路摄像头）时，单Hub直连所有Worker的扇出开销过大。G6实现了2级Hub层级架构：

| 部署模式 | Hub角色 | 适用规模 | 说明 |
|----------|---------|----------|------|
| **standalone** | 独立Hub，直连所有Worker | 1-125节点（500路以内） | 默认模式 |
| **regional** | 区域Hub，管辖区域内Worker，对Central Hub表现为"大Worker" | 每区域≤125节点 | 区域自治 |
| **central** | 中心Hub，管辖多个Regional Hub | 理论无上限 | 跨区聚合 |

**搜索路径**: Central Hub → 并行查询Regional Hubs → 各Regional并行查询本区Worker → 结果逐级聚合返回。

**实现**: `internal/search/hierarchical.go` 定义 `HubMode`、`RegionalHub` 结构，Regional Hub 在联邦搜索中被视为 NodeType=regional 的节点。

#### 8.1.3 告警规则类型
